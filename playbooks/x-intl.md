## 前提认知（2026 平台机制）

## 登录态检查

打开 x.com 任意搜索页：能出 Latest 流 = 已登录。登出态搜索直接不可用。

## 关键词验证协议（三指标抽样法）

搜索 URL：`https://x.com/search?q=<编码后查询>&f=live`
查询模板：`"<关键词>" min_faves:20 lang:en -filter:replies`

每词采样后按三指标打分：①意图纯度（发帖者是否目标人群）②需求量（单位时间过赞线
帖数）③目标体量出现率（抽查发帖者粉丝数落 3千–30万 段比例）。

**min_faves 分层规律（重要实测发现）**：`min_faves:20` 筛出的是"清单帖工厂"层
（高转发资源帖账号）；**找合作博主用 `min_faves:5 -filter:links` 的低赞原创层**，
那里才是真人创作者。高赞层只用来找放大器账号。

## 采集 JS（实测，防超时版）

```js
// Latest 流帖子采集：短循环（5 轮）防 CDP 45s 超时，长循环会冻结渲染器
window.__samp = {};
const seen = window.__samp;
function harvest() {
  document.querySelectorAll('article').forEach(a => {
    const link = a.querySelector('a[href*="/status/"]');
    if (!link) return;
    const id = link.href.split('?')[0];
    if (seen[id]) return;
    const userEl = a.querySelector('[data-testid="User-Name"]');
    const textEl = a.querySelector('[data-testid="tweetText"]');
    seen[id] = { user: userEl ? userEl.innerText.replace(/\n/g, ' | ') : '?',
                 text: textEl ? textEl.innerText.slice(0, 120).replace(/\n/g, ' ') : '' };
  });
}
for (let i = 0; i < 5; i++) { harvest(); window.scrollBy(0, 1400); await new Promise(r => setTimeout(r, 1200)); }
harvest();
Object.entries(seen).map(([id, v]) => v.user + ' :: ' + v.text).join('\n---\n') || 'EMPTY';
```

坑：① 自动滚动单页稳定上限约 8 条（虚拟列表+加载限制），要更大样本上 X API，
不要硬滚 ② `scrollTo(bottom)` 不触发加载，用 `scrollBy(1400)` 步进
③ `window.__samp` 跨查询要重置。

粉丝数抽查（主页）：
```js
(document.querySelector('a[href$="/verified_followers"]')?.innerText || 'N/A').replace(/\n/g, ' ')
```

## 粉丝数前置核验（实测与出价依据，不是触达门禁）

**实测教训**：首轮 5 位种子候选核验后仅 1 位通过硬门槛（转化率 20%），
失败原因全部是**粉丝量级**而非垂类不符：

| 候选 | 种子预判 | 实测粉丝 | 结果 |
|---|---|---|---|
| <账号27> | 待触达 | 18.8K | ✅ 唯一通过 |
| <账号Y> | A 档首选 | 76.6K | 超阈值 53% 待审 + 内容漂移 → 降观察 |
| <账号Z> | 暂缓·放大器池 | 200.4K | 超阈值 301% → 放大器池 |
| <账号B> | B 档 | 1,017 | ❌ 低于 3 千线 + 公司号 |
| <账号A> | B 档 | **42** | ❌ 远低于 3 千线 |

**结论与纪律**：

- **X 上技术影响力与粉丝数弱相关**——GitHub 高星项目作者（90.9k 星 / 13.8k 星列表
  维护者）X 粉丝可能只有三位数甚至两位数。GitHub 星数**不可**作为 X 粉丝量的代理指标。
- 因此：**从 GitHub/awesome 列表反查来的候选，必须先抓 X 粉丝数**。
  若创作者内容方向相符，即使低于 3 千或超过 5 万也入库标 `待触达`，
  粉丝量级写入 notes/approval 供出价。其 awesome 列表资产另记 `channels.csv`，
  因为免费上榜位与付费博主触达是两种价值，不混算但可同时保留。
- 关键词搜索层（低赞原创层）产出的候选反而更可能落在目标粉丝带，
  优先跑关键词层、GitHub 反查层只做补充。
- **内容漂移复核**：种子记录与实测可能间隔数周，AI 工具赛道术语与创作者关注点
  迁移很快（本轮 <账号Y> 已从 Claude Code 转向 Cursor/Codex）。
  触达前必看近期 5 帖，bio 不足以判断当前内容线。

## 7. 内容真实性核验（增长号/清单帖工厂识别，2026-08-11 实测定稿）

**问题**：关键词命中 + 垂类方向对 + 粉丝量在带内，三项硬门槛全过，仍然可能不是
一个真实分享内容的人，而是专门做"涨粉/带货清单帖"生意的账号。**这类账号靠
bio 和粉丝数筛不出来**——bio 往往写得很像真实创作者（"I build stuff""tracking
how AI is built"），必须翻近 5–10 条实际发帖才能看出来。本节三类信号来自
2026-08-11 一轮 8 人复核（<账号63>/<账号64>/<账号66>/m0h/<账号71>/<账号98>/<账号95>/
<账号101> 全部改判淘汰）。

### 7.1 三类信号，命中任意一条→单独标"疑似增长号"，人工翻 5–10 条帖复核

| 信号 | 识别特征 | 本轮案例 |
|---|---|---|
| **标题党式数字宣称** | 帖子结构是"[年龄/身份]靠[工具]赚了$[具体数字]"，强调结果不強调方法，常年大写开头 | <账号63>："20岁小孩靠AI内容工厂一个月赚$3.7万"；<账号98>："ANTHROPIC LEAKED A SETUP...17岁在OpenAI年薪$140万" |
| **纯清单帖** | 无个人观点/项目背书，纯罗列"N个xxx工具/技巧"，常配转发名人语录蹭流量 | m0h："20个agentic skills清单""top 50 MCP servers清单"+转发Zuckerberg/Jobs语录 |
| **互关互赞涨粉话术** | 直接呼吁"verified的关注一下互relate/help each other reach [某数字] followers" | <账号95>："If you're verified, make some noise so I can follow you and we can help each other for reach this damn 500K" |

bio 本身也是一个弱信号，可以辅助判断但不单独作为淘汰依据：写"tracking AI
income streams"（明确搞钱定位）比"I build Micro-SaaS tools"（具体项目名）
更可疑，后者仍需翻帖验证（<账号95> 就是 bio 看起来正常、翻帖才发现问题的案例）。

### 7.2 品牌安全信号（单独一类，不算增长号，但同样"翻帖才能发现"）

技术内容本身可能是真实的，但时间线混有明显党派/地域争议内容，命中即淘汰，
不因技术内容真实而豁免（本轮 <账号71>：FStar/依赖类型语言内容属实，但混有
明确党派政治评论）。

### 7.3 垂类判定的另一个教训："泛旅行"标签放得太宽

<账号101> 案例：此前 notes 标"泛旅行博主，触达角度需扣行程规划"，翻帖后
发现实际内容是新西兰/法国等**飞机可达**目的地攻略（275 篇博客更新清单），
跟"自驾"完全不沾边。教训：**"泛旅行"不是一个够精确的中间态标签**，翻帖时要
明确区分"内容是不是围绕开车/自驾"，模糊地带不要靠"调整触达角度"这种话
自我说服留下，判定不了就直接淘汰，不要为了凑数硬发（比照 direction-only
政策本身的边界：方向不符仍然淘汰，硬门槛之外的软性判断同理）。

## 8. 发现层前置检查清单（每次开一轮新的 X 采集之前，逐条勾过）

**起因**：07-28 就写了"旅行词在X全部无效"，08-10 那轮采集仍然用
`road trip itinerary`/`car camping` 去搜 X，直接导致 <账号101>、
<账号102> 两个非自驾账号进库，事后要靠人工一条条翻内容才揪出来、判淘汰——
一次就烧掉一整轮的人工和 token。规则写在文档里不代表会被执行，这份清单
就是把"应该记得"变成"开工前 2 分钟必须过一遍"：

1. **本轮关键词表里有没有旅行/自驾类词（road trip/car camping/vanlife/
   overlanding/national park 等）**？有 → 删掉，这些词只在 Collabstr/IG
   发现层用，X 上无效（第 0 节「前提认知」的结论，不是这次才定的）。
2. **`min_faves` 设的是多少**？找合作博主用 `min_faves:5 -filter:links`
   （低赞原创层）；`min_faves:20` 及以上只用来找放大器候选，不要用来找
   常规触达对象——高赞层系统性偏向清单帖工厂（§7.1 三类信号的账号几乎
   全部会从高赞层冒出来）。
3. **粉丝量粗筛在验证前先过一遍，不要等验证完才发现超线**：抓到候选后
   先用 mirror/主页展示的大致粉丝量排一遍序，明显超过 `followers_max` 的
   2 倍以上（如 10 万+ 走 3千–5万 门槛），除非本轮目标就是找放大器/报价
   基准候选，否则不进入逐人核验队列，省下来的核验时间用来多验证几个
   量级合适的候选。
4. **本轮结束前跑一次 §7 的三类信号自查**：抽查已入库候选里粉丝量最大的
   3–5 个和最近发帖频率最高的 3–5 个（这两类最容易是清单帖工厂或超线号），
   而不是等到要触达那一刻才发现问题。
5. **每个入库候选必须写 `source_keyword=`**：X 线前 25 行全部漏记，导致
   "哪个词产出了哪个候选"完全无法审计，而本节整套检查表都依赖这个反馈闭环。
   2026-08-17 已按 collected_at 批次回填至可考证的粒度（详见 §9）。

## 9. 品类词 > 身份词（2026-08-17 实测定稿）

**一轮失败 + 一轮成功换来的结论**：X 关键词层反复捞出"推自己产品的人"，
不是词还不够垂，是**词的类型选错了**。

- **身份词**（`indie hacker`、`build in public`）搜的是"这个人是谁"。
  `indie hacker` 按定义就等于"自己做产品的人"，换任何近义词都跑不掉这个人群。
- **行为词**（`here's how I`、`tutorial`、`walkthrough`）本以为能筛出教程/测评型，
  实测完全无效：在 X 上这类措辞恰好被两拨人垄断——演示自己产品的创始人，
  和拿它当互动钩子的增长号。14 个账号 0 个合格。
- **品类词**（`agent skills`）搜的是"在聊什么"，也就是**产品所属的品类本身**。
  同样一轮采集，产出 4 个可用候选。

**执行纪律**：开新一轮 X 采集时，词表里至少要有一个"产品品类词"打头，
身份词只作补充。品类词随产品形态变（现在是 agent skills，将来产品若变成
MCP server 或别的形态，品类词跟着换，每季度重验时一并刷新）。

### 9.1 「文件名词 > 话题词」的验证结果：假设一半成立，但不能照搬（2026-08-17 对照实验）

从第一轮观察到"`SKILL.md` 出真人、`claude skills` 出营销号"，提了个假设：
越像文件名的词越干净。设对照组实测（同口径 `min_faves:1~3` 低赞原创层，
逐账号留档在 `海外社媒/intl-expansion-20260817/discovery_checkpoint.json`）：

| 词型 | 样本词 | 去重账号 | 内容真实 | 纯度 | 落带内可用 |
|---|---|---|---|---|---|
| 品类词（上一轮） | `agent skills` / `SKILL.md` / `AGENTS.md` | ~30 | — | — | **8（≈27%）** |
| 文件名/配置词 | `.claude/skills`、`mcp.json`、`settings.json`、`hooks.json`、`.mcp.json`、`subagent` | 16 | 5 | **31%** | **0** |
| 话题词（对照） | `prompt engineering`、`my newsletter/this week in` | 13 | 1 | **8%** | **0** |

**结论一：纯度上假设成立**（31% vs 8%，近 4 倍）。话题词那 13 个里 12 个是
赠课、互关话术、语录农场、粗体 unicode 清单、crypto——`prompt engineering + claude`
这一个词就同时命中了 §7.1 的全部三类信号。

**结论二：但可用率两组都是 0，所以不能照搬。** 文件名词筛出来的真人粉丝量是
222 / 418 / 958 / 1,041 / 1,494——干净但全在 3 千线以下。这不是巧合：
**会打出 `mcp.json`、`hooks.json` 的人正在调自己的配置，是在跟同行说话，不是在
面向受众发布**；而 `SKILL.md` / `AGENTS.md` 出现在"我做了个 skill / 这个标准是什么"
这类**面向受众宣布产物**的句子里，发这种话的人才需要有受众。

**所以真正的变量不是"文件名 vs 话题"，是"在不在谈论一个可分享的产物"**：

- ✅ **产物词**（`agent skills`/`SKILL.md`/`AGENTS.md`）——有人宣布、有人围观，
  发帖者既真实又有受众。**开新一轮优先用这一类。**
- ⚠ **配置词**（`mcp.json`/`settings.json`/`hooks.json`）——内容质量最高，
  但人几乎全在 3 千线下。**只在专门补"低粉高质量/技术背书"位时用，不要指望出腰部。**
- ❌ **话题词**（`prompt engineering`/`context engineering`/`claude skills` 复数）——
  纯度 8%~14%，直接淘汰。
