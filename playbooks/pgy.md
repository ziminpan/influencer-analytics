## 这是什么、为什么优先

蒲公英 = 小红书官方达人商单平台（pgy.xiaohongshu.com）。品牌号登录后可以**自助**看到
达人的官方后台级数据——不用再问博主要截图。它是估算精度阶梯的新顶层：
**蒲公英官方值 > 博主后台截图 > 逐账号抽样 > 类目先验**。
对账之后，整库数据从"估算可信"升级为"官方可审计"。

## 前置

- 公司蒲公英品牌号已开通，当前浏览器已登录 pgy.xiaohongshu.com
  （登录态检查：打开首页看右上角是否显示品牌账号名；未登录停下请用户处理）。
- 只查询**已入库/候选**博主，不做全站漫游式浏览。

## 目标字段（搜索昵称 → 达人主页）

| 蒲公英字段 | 写入 | 说明 |
|---|---|---|
| 阅读中位数（近30/90天） | `official_reads_median`，并覆盖 `expected_exposure` | data_confidence=high |
| 互动中位数 | 与库内 `median_engagement` 对账，不覆盖；差异大记 notes | 蒲公英口径=赞藏评合计 |
| 图文/视频一口价（刊例价） | `quote_image` / `quote_video`，`quote_notes` 标"蒲公英刊例" | 刊例≠成交价 |
| 粉丝画像（性别/年龄/地区） | `score_audience` 的打分依据，摘要进 notes | 补上此前常缺的维度 |
| 近90天商业笔记数 | notes（商单密度：过高=粉丝疲劳，过低=不熟流程） | — |

## 流程

1. 逐昵称搜索，节奏与主站一致（间隔 ≥45s，一批 ≤8 个后休息）。
2. 达人数据区**截图留档**（原始凭据，同 raw_samples 思想）。
3. 官方值走 `ingest.py` 刷新机器列（official_reads_median / expected_exposure / cpm 联动）。
4. AD 备注写"蒲公英官方值 YYYY-MM"。
5. 凑够 ≥8 个「官方阅读 vs 库内估算」对照后：比值中位数 → 修正 config 的
   `xhs_read_multiplier`（人工确认后写回，CHANGELOG 记一行）。

## 已知事实与坑

- 达人入驻门槛粉丝 ≥1000：搜不到 = 未入驻或粉丝不足 → 保持估算值，notes 标"未入驻蒲公英"。
- 刊例价普遍高于私聊底价；两个数都留（quote_notes 区分），CPM 按实际拟付口径算。
- 走蒲公英报备的内容不限流、可投流；私下合作有限流风险——这正是
  `budget_planned = 报价 × (1 + platform_fee_rate)` 当初的设计原因。
- DOM 选择器：待首次实采时在此补 JS 片段。**结构未实测前不写、不跑**（与海外平台同纪律）。
